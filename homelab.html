#3

Backup drive threw file system errors after recabling

Resolved Nov 2026
Problem
After moving network cables, every boot filled the console with EXT4-fs error checksum messages from the backup drive.
Cause
The USB backup drive was disturbed while Proxmox had it in use, leaving its file system out of sync.
Fix
Took the storage offline, unmounted it, repaired it, and brought it back: 
pvesm set T7-backup --disable 1
umount /mnt/pve/T7-backup
fsck.ext4 -f -y /dev/sda1
mount /dev/sda1 /mnt/pve/T7-backup
pvesm set T7-backup --disable 0
Verified with a reboot: 0 errors, and the 2.6 GB VM backup was intact.
Lesson
Never unplug storage that's in use. Shut the host down first, and confirm a fix with a restart.
#2

Lost the network after moving the switch to a wall jack

Investigating Nov 2026
Problem
The Proxmox web page stopped loading. The link light was up, but ping 192.168.1.254 returned Destination Host Unreachable.
Diagnosis
Ruled out the host: ip -br link showed the adapter UP, and other wired devices still got addresses from the router. The problem is in the wall-jack path.
Workaround
Rolled the uplink back to the previous path. Everything came back with no config changes.
Next
Trace the wall jack to the router, one cable at a time.
#1

Couldn't log in to the Proxmox web interface

Resolved Nov 2026
Problem
My login kept failing on the Proxmox web page.
Cause
I was using my Ubuntu VM username. Proxmox's administrator is root, signing in through the Linux PAM realm.
Lesson
Every system has its own accounts. Store each one in a password manager.
